# Защита проекта Qadam

Qadam — клиентский планировщик задач, привычек и фокус-сессий. Он продолжает midterm и endterm: знакомые страницы и прежние функции сохранены, final добавляет API, ООП, полный CRUD, статистику и настройку размера текста. Данные хранятся в браузере; серверной базы и аккаунтов нет.

## Подготовка перед показом

1. Запустите из папки проекта `python3 -m http.server 8000` и откройте `http://localhost:8000`. Публикация обновлённой версии отложена; используйте её публичный адрес только после отдельного развёртывания и проверки.
2. Используйте отдельный профиль браузера для демонстрации. Не очищайте данные своего обычного профиля и не вставляйте команды изменения `localStorage` во время защиты.
3. Подготовьте вкладки Today, Calendar и Statistics. Создайте только демонстрационную задачу с названием `Защита Qadam`, сегодняшней датой, категорией Study и заметкой.
4. Откройте исходники `js/app.js`, `js/tasks.js`, `js/weather-model.js`, `js/weather.js` и модуль своей части.
5. Проверьте интернет: API и внешние Bootstrap, jQuery, иконки и шрифты используют сеть. Открытие через `file://` для ES-модулей не подходит.
6. Каждый должен объяснять весь проект. На защите каждому задают минимум четыре вопроса; могут попросить найти, изменить или отладить код.

### Вопросы Adil

1. **Что здесь является классом, а что объектом?** `ForecastDay` — описание общих свойств и методов. Каждый результат `new ForecastDay(...)` — отдельный объект конкретного дня со своими значениями.
2. **Зачем ООП, если можно хранить обычные объекты?** У дня есть и данные, и связанное поведение: форматирование температуры, описание погоды и подсказка. Класс собирает это в одном месте. Это не означает, что весь проект обязан использовать классы.
3. **Что делает `await`?** Ждёт результат Promise внутри `async`-функции. Ожидание запроса не блокирует весь интерфейс. `response.json()` также возвращает Promise.
4. **Почему нужен `response.ok`, если есть `catch`?** `fetch` обычно не отклоняет Promise только из-за HTTP 404/500. Мы сами проверяем HTTP-статус и выбрасываем ошибку; `catch` также обрабатывает сбой сети и неверный JSON.
5. **Как защищаетесь от некорректного API-ответа?** `createForecastDays` проверяет массивы, одинаковую длину, реальные даты, конечные числа, диапазон температуры и целый код погоды. Неверные данные не превращаются в выдуманные карточки.
6. **Что будет при быстром выборе двух городов?** Новый запрос отменяет предыдущий. Дополнительная проверка `currentRequest !== request` не позволяет устаревшему запросу менять результат и состояние кнопки.

### Вопросы Asyl

1. **Как считается процент выполнения?** В `renderStatistics`: число завершённых делится на общее число задач, умножается на 100 и округляется. При пустом массиве результат 0%, чтобы не делить на ноль.
2. **Чем отличаются `filter`, `map` и `reduce`?** `filter` выбирает записи; `map` преобразует каждую запись; `reduce` собирает итог. В `getFocusWeek` сначала выбираются сессии определённой даты, затем складываются `minutes`.
3. **Почему событие `storage` не решает всё?** Оно уведомляет другие вкладки того же origin, а не вкладку, которая записала значение. Для текущего документа `writeStorage` отправляет собственное `qadam:data-changed`; также используются обновление при фокусе и явная кнопка.
4. **Как график остаётся понятным без цвета?** У каждой строки есть текстовая подпись и числовое значение. Декоративная полоса имеет `aria-hidden`, поэтому информация не зависит только от её цвета и длины.
5. **Как сохраняется размер текста?** Допустимы 100, 112 и 125. Значение пишется JSON-числом в `qadam-text-size`; при загрузке проверяется и применяется к `document.documentElement.style.fontSize`.
6. **Что важно при расчёте календаря?** `getMonthDays` вычисляет первый/последний день месяца и отступ до понедельника. `changeMonth` ограничивает выбранный день последним днём нового месяца: 31 января → 28 или 29 февраля. Дата задачи сравнивается как календарная дата `YYYY-MM-DD`, без случайного сдвига из-за перевода в UTC.

### Вопросы Nurlan

1. **Где полный CRUD?** Create — новая запись в `submitTask`; Read — `getVisibleTasks` и `renderTasks`; Update — режим редактирования и `Object.assign(task, values)`; Delete — `deleteTask`. Cancel сбрасывает форму, не меняя запись.
2. **Почему проверять форму через JS, если есть HTML-атрибуты?** Нужны конкретные правила и сообщения: название 3–80 символов, существующая дата, разрешённая категория, корректное время, заметка до 240 символов. `validateTaskForm` возвращает boolean; неверная форма не доходит до сохранения.
3. **Для чего `preventDefault()`?** В обработчике `submit` он предотвращает стандартную отправку и перезагрузку страницы. После этого приложение само проверяет форму, обновляет массив, DOM и сохранённые данные.
4. **Почему нужны `JSON.stringify` и `JSON.parse`?** `localStorage` хранит строки. Первый превращает массив/объект в JSON-строку; второй восстанавливает значение. После разбора ещё нужна проверка структуры, потому что корректный JSON может оказаться неподходящим объектом.
5. **Чем отсутствие ключа отличается от `[]`?** Отсутствующий ключ может означать первый запуск и загрузку начальных данных. `[]` — намеренно пустой список после очистки; его нельзя заменять стартовыми задачами.
6. **Где применён jQuery?** В `setupTaskJQuery`: делегированные клики по избранному, удалению и подробностям; ID- и class-селекторы; обход DOM через `closest`/`find`; эффекты `fadeOut`/`slideToggle`. Если библиотека не загрузилась, `setupNativeTaskActions` сохраняет базовые действия без этих анимаций.
7. **Почему старый streak может отличаться от истории?** `normalizeHabit` сохраняет старый счётчик отдельно в `legacyStreak`, но в `dates` переносит только известные даты. Число 12 не создаёт 12 выдуманных отметок. `longestRecordedRun` считает только реально записанные даты; при пропуске дня текущая серия прерывается.

## Общие вопросы для каждого

1. **Что такое DOM?** Представление HTML как дерева объектов. Мы находим узлы через селекторы, меняем `textContent`, атрибуты и классы, создаём или удаляем элементы. `buildForecastCard` использует `createElement`; список задач перерисовывается из массива.
2. **Почему события делегируются списку?** Карточки создаются и заменяются динамически. Обработчик на общем контейнере продолжает работать; `event.target.closest(...)` находит конкретную кнопку и её карточку. `target` — исходный элемент, `currentTarget` — элемент обработчика.
3. **Где требуемые массивы и циклы?** Категории, задачи и привычки — массивы в `js/data.js`; `renderTasks` распределяет задачи по группам и проходит по группам. `forEach` заполняет варианты категорий; `map` создаёт разметку карточек.
4. **Какие события реально используются?** `input` — поиск и редактирование; `change` — фильтры, чекбоксы и настройки; `click` — действия; `submit` — форма. Дополнительно: `storage`, `focus`, `visibilitychange` и собственное `qadam:data-changed`.
5. **Почему `const` не делает объект неизменяемым?** Оно запрещает переназначить переменную, но не запрещает менять свойства объекта или содержимое массива. Для переназначаемого списка `tasks` применяется `let`.
6. **Как избегаете вставки HTML из текста пользователя?** Динамический текст помещается через `textContent` либо экранируется `escapeHTML` перед включением в шаблон. Пользовательская строка не должна становиться исполняемым HTML.
7. **Почему таймер не уменьшает счётчик ровно раз в секунду?** Фоновая вкладка может задерживать интервалы. `tick` вычисляет остаток по `deadline - Date.now()`. Интервал лишь обновляет экран. При перезагрузке незавершённая сессия сбрасывается; завершённые сохраняются.
8. **Какие ограничения у хранения?** Данные принадлежат текущему origin и профилю браузера. Другой компьютер или домен не получает их автоматически. При отказе записи `writeStorage` возвращает `false` и показывает предупреждение; это не успешное сохранение.
9. **Что делать с ошибкой во время защиты?** Назвать ожидаемое поведение, воспроизвести шаги, посмотреть Console/Network и конкретный обработчик. Не выдавать старые данные за новый успешный ответ API и не исправлять ошибку очисткой личных данных.

## Безопасная демонстрация сетевой ошибки

1. В тестовом профиле сначала полностью загрузите Calendar с работающей сетью.
2. Откройте DevTools → Network, включите Offline и нажмите Refresh forecast. Не перезагружайте весь сайт: это одновременно заблокирует HTML, модули и CDN.
3. Покажите понятное сообщение об ошибке и доступную кнопку повторного запроса. Сохранённые задачи при этом не изменяются.
4. Верните No throttling/Online, нажмите Refresh forecast и дождитесь карточек. Завершите демонстрацию с работающей сетью.
5. Если показываете блокировку только API, заблокируйте запрос к `api.open-meteo.com` и затем удалите правило. Не подменяйте реальные пользовательские данные.
